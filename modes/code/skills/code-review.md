# Code Review Skill

Use when reviewing changes, diffs, implementation plans, or risky code paths.

Review for:

- behavior changes
- edge cases
- security issues
- data loss risk
- concurrency or state bugs
- missing or weak verification

Report issues with severity and concrete evidence.

Output:

- severity
- affected area
- evidence
- likely impact
- suggested direction when useful

Avoid:

- long summaries before findings
- nitpicks that do not change behavior, risk, or maintainability
- ungrounded claims about code paths that were not inspected
