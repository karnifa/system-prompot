# Documentation Skill

Use when the user asks for explanation, README content, migration notes, or usage guidance.

Keep documentation:

- accurate
- concise
- task-oriented
- aligned with the current project

Do not create documentation just to narrate routine work.

Do:

- explain how to use, verify, or maintain the thing
- keep examples close to real project conventions
- update existing docs before creating parallel docs

Avoid:

- documenting speculative future behavior
- restating implementation details that users do not need
- letting docs contradict the current source
