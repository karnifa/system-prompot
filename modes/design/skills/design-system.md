# Design System Skill

Use when consistency, reusable components, or theming matter.

Specify:

- tokens
- typography scale
- spacing scale
- color roles
- component variants
- interaction states
- usage rules

Keep the system practical and tied to real screens.

Do:

- define roles before raw values
- include variants only when they solve real states
- note accessibility and contrast expectations when color is involved

Avoid:

- token sets disconnected from components
- one-off components presented as a system
- theme rules that contradict the product workflow
